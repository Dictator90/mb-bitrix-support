# Changelog

## 0.1.1 — 2026-07-31

- **`File\Image`: пакетная обработка вариантов.** `ImageBuilder::resolveMany()`, `ImageProcessor::processMany()` и `DatabaseImageCache::getMany()` разрешают набор вариантов одной выборкой кэша и одной загрузкой данных файлов вместо запроса на каждый вариант (нужно для адаптивных картинок с `srcset`). Проверка существования таблицы кэша выполняется один раз на процесс. Публичные `ImageBuilder::getOperations()` / `getFormat()` / `getQuality()` открывают параметры варианта наружу.

- **`FileService` / `FileRepository`: запись в `b_file` починена.** ORM-путь (`FileTable::add` / `update` / `delete`) на любой актуальной версии ядра бросает `NotImplementedException('Use CFile class.')` — то есть `app('file.service')->save()`, `updateDescription()` и `deleteFile()` не работали вовсе, а `deleteFile()` успевал удалить физический файл до падения и оставлял осиротевшую строку в `b_file`. Теперь: запись — `CFile::DoInsert()` (он же кладёт `FILE_HASH` в `b_file_hash` и рассылает `OnAfterFileSave`), описание — `CFile::UpdateDesc()`, удаление — `CFile::Delete()` (физический файл, ресайзы, хэш, дубликаты, квота, события `OnFileDelete` / `OnPhysicalFileDelete`, чистка кэша). `deleteFile()` / `FileRepository::delete()` возвращают `false` только когда файла с таким ID нет: файл, на который ссылаются дубликаты, ядро помечает удалённым и сносит вместе с последней ссылкой — это успех. Удалены осиротевшие `FileService::deletePhysicalFile()` и `diskQuotaNotifyDelete()` — их работу делает ядро. В `scripts/dev/bitrix-phpstan-stubs.php` добавлен стаб `CFile`.
- **Дедупликация приведена к семантике ядра.** `DuplicateResolver::resolve()` возвращал ID уже существующего файла — несколько сущностей делили одну строку `b_file` без счётчика ссылок, и первое же (теперь рабочее) удаление сносило файл у всех владельцев. Теперь, как в `CFile::SaveFile()`, создаётся своя строка `b_file` поверх той же физической копии (`SUBDIR` / `FILE_NAME` оригинала, без `FILE_HASH`) и регистрируется связь в `b_file_duplicate` — ядро сносит файл вместе с последней ссылкой. Если оригинал исчез, резолвер возвращает `0`, и `saveFile()` сохраняет файл обычным путём. Резолвер получил необязательную зависимость `FileRepositoryContract`.
- **`FileService`: метаданные файла, переданного содержимым.** Для `['content' => ...]` без пути на диске `WIDTH` / `HEIGHT` оставались нулями, а `CONTENT_TYPE` при незаданном `type` становился `unknown`. Теперь размеры берутся `getimagesizefromstring()`, MIME — оттуда же с откатом на `finfo` и `application/octet-stream`. Дедупликация по хэшу (`DuplicateResolver`) не менялась.

- **Вынос построения админки (заменено `mb4it/bitrix-admin-kit`):** из пакета удалены подсистемы `EntityView`, `Settings` и `UI\Base` / `UI\Control` / `UI\Providers` / `UI\Traits`. Оставлены Bitrix-специфичные `UI\EntitySelector\*` (провайдеры для селекторов) и `UI\Admin\MenuIcon` — на них опирается admin-kit. `Module\Entity` / `ModuleContainer` лишились методов `getPageManager()` / `pageManager()` (мёртвый API старого дерева настроек); `adminKit()` сохранён.
- **Contracts вынесены в `mb4it/bitrix-contracts`:** каталог `src/Contracts/*` удалён; интерфейсы `MB\Bitrix\Contracts\*` теперь поставляются пакетом `mb4it/bitrix-contracts` (тот же namespace, drop-in). Добавлена зависимость `mb4it/bitrix-contracts` в `require`.
- **Оставлены как расширения Bitrix (не дубликаты):** `Filesystem` (фасад над `mb4it/filesystem` с привязкой к `DocumentRoot`), `Logger` (на `Bitrix\Main\Diag\Logger`, Bitrix event log), `File`/`File\Image`.

- **`FileService` (DI):** экземплярный сервис, контракт `MB\Bitrix\Contracts\File\FileServiceContract`; в контейнере `app('file.service')` и тот же singleton по классу контракта; алиас `save()` → `saveFile()`; `FileService::method()` через `__callStatic` делегирует в `resolve()`; провайдер `MB\Bitrix\File\ServiceProvider`; классы `File\Image\*` принимают опционально `FileServiceContract` или используют `FileService::resolve()`.
- **`FileService` (D7):** мутации `b_file` (изначально через `FileTable`, см. исправление выше — теперь через `CFile`); события `OnMakeFileArray` / `OnGetFileSRC` через `Bitrix\Main\Event`; единый `Loader::getDocumentRoot()`; валидация имён и расширений без `CBXVirtualIo` / глобальных `GetFileName` / `IsFileUnsafe`; транслит через `Bitrix\Main\Text\Transliterator` при наличии класса; квота — тонкие вызовы `CDiskQuota` с `@internal`; кеш строк файла — приватный `FileService::$fileDataCache`; `getFilesData` возвращает `null` для отсутствующих ID; трейт `RememberCachable::__callStatic('remember')` возвращает значение.
